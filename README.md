## 概述

本skill帮助运营商客户经理/解决方案经理，将需求洞察报告和弹药库（产品资料）转化为面向客户决策层的SPAR格式解决方案建议书。

**SPAR结构**：
- **S（Scene）**：客户场景与现状描述
- **P（Problem）**：痛点与影响分析
- **A（Answer）**：解决方案如何解决问题
- **R（Result）**：预见的效果与价值

## 输入材料

1. **客户背景资料**：客户拜访纪要、4L/4S洞察报告、一企一档、企业官网信息等
2. **弹药库（产品平台库）**：由学员在提示词中指定路径或内容

### 材料充分性判断（必须遵守）

收到客户背景资料后，**必须先判断材料是否充分**，再进入五步法分析：

1. **充分性评估维度**：
   - 客户基本信息：行业、规模、主营业务、组织架构
   - 痛点与需求：明确的业务痛点、已尝试的解决方案及效果
   - 竞争环境：竞争对手/同行已做的相关投入与成效
   - 决策链信息：关键决策人、推进节奏、预算约束
   - 行业背景：客户所在行业的数字化现状、政策导向、技术趋势

2. **材料充分**：覆盖上述3个及以上维度 → 直接进入五步法

3. **材料不够充分**：覆盖不足3个维度 → **必须联网搜索补充**，规则如下：
   - 使用 `online_search` 搜索客户官网、政府公示平台、权威行业报告等官方信源
   - 搜索关键词示例：`[客户名称] 官网`、`[行业名称] 数字化转型 政策`、`[客户名称] 招标`、`[地区] [行业] 产业政策`
   - **只采纳官方权威来源**（.gov.cn、客户官网、上市公司公告、央媒报道、行业白皮书等）
   - **严禁编撰**任何未在资料中出现的具体数据、人名、金额
   - 搜索补充的内容必须标注来源（如"来源：XXX官网/XXX政策文件"）
   - 搜索后仍无法获取的信息，在分析报告中明确标注"该信息缺失，建议后续拜访确认"

4. **判断结果告知学员**：在进入五步法前，用1-2句话简要说明材料充分性判断结论及是否进行了联网补充

### 弹药库获取规则（必须遵守）

1. **学员提示词中指定了弹药库**：直接读取并使用
   - 可能是本地目录路径（如 `D:\产品资料\弹药库`）
   - 可能是文件路径（如 `弹药库.xlsx`）
   - 可能是附件引用（如 `@弹药库`）
2. **学员提示词中未指定弹药库**：必须先询问学员是否可提供弹药库位置
   - 使用 question 工具提问："您是否有本地弹药库（产品平台资料目录/文件）？如有请提供路径，我将读取匹配。"
   - 选项：a)"我提供弹药库路径" b)"没有弹药库，用常规运营商产品"
3. **学员确实无法提供弹药库**：使用"常规运营商弹药库"作为默认
   - 常规弹药库覆盖7大类：基础通信（5G/专线/SD-WAN）、云网融合（云主机/专属云/边缘云）、云通信（视频云/千里眼/应急广播）、物联网（IoT平台/传感器/连接管理）、行业应用（数字乡村/智慧园区/智慧政务等）、安全（等保/量子加密/安全运维）、行业解决方案（应急/文旅/教育/医疗等）
   - 标注为"常规弹药库——未匹配属地化产品资料，差异化能力和报价参考可能需后续补充"

## 处理流程：五步法

### Step 1：需求转译

将客户的"大白话"转化为技术语言和能力方向。

| 客户原话 | 需求本质 | 技术语言 | 能力方向 |
|---------|---------|---------|---------|
| 村里事情太杂了，档案找不到 | 信息散乱、查询困难 | 智慧村务SaaS + 数据中台 | 业务应用 + 算力存储 |
| 种茶叶靠天吃饭，风险大 | 靠经验、风险高 | 需要农业IoT，传感器监测 | 采集感知+业务应用 |

**穿透层级判断**：
- S1：表层需求（功能诉求）
- S2：中层需求（效率/流程诉求）
- S3：深层需求（管理效率）
- S4：顶层需求（战略/政绩）

### Step 2：能力匹配

围绕"数据生命周期"，逐维度判断客户需求：

| 能力维度 | 判断问题 | 对应需求 |
|---------|---------|---------|
| 采集感知 | 数据入口，需不需要感知/监控？ | 传感器、IoT、视频监控 |
| 安全保密 | 数据护航，需不需要等保/安全合规？ | 等保、安全网关、加密 |
| 网络传输 | 数据搬运，需不需要联网/互联？ | 5G专网、专线、SD-WAN |
| 业务应用 | 数据变现，需不需要行业方案/系统？ | SaaS、行业平台、APP |
| 算力存储 | 数据落地，需不需要上云/建机房？ | 公有云、专属云、边缘云 |
| 分析智能 | 数据增值，需不需要AI/数据分析？ | 大模型、数据中台、AI中台 |

### Step 3：产品组合 + 自研检查

**三层产品组合**：
1. **基础业务层**（必备底座）：网络传输 + 算力存储
2. **战新产品层**（利润来源）：采集感知 + 分析智能 + 安全保障
3. **重点平台层**（差异化核心）：业务应用 + 分析智能

**组合四原则**：
- 基础打底：方案必须有基础业务
- 战新增值：战新产品是利润来源，需1-2个
- 平台拔高：重点平台是差异化核心
- 按需组合：非所有方案都上三层，由客户需求决定

### Step 4：差异化定位

从三个维度建立差异化优势：

**安全可信**：
- 等保三级/密评
- 数据本地化存储不出省
- 自主可控（国产化）
- 量子加密（可选）

**稳定可靠**：
- 99.99%可用性
- 属地化支撑团队
- 7×24运维分钟级响应
- 端到端SLA保障

**智能领先**：
- 模型平台（300+模型）
- 行业大模型
- 算网调度能力
- 创新应用能力

### Step 5：价值量化

**五维价值模型**：

| 价值维度 | 核心说明 | 优先呈现对象 |
|---------|---------|-------------|
| 直接效益 | 收入增长/业务增量 | 功能诉求型 |
| 成本节省 | 运维/人力/流程成本 | 资产诉求型 |
| 风险规避 | 安全/合规/业务连续性 | 情绪诉求型 |
| 战略价值 | 标杆效应/考核对标/生态卡位 | 品牌诉求型 |
| 情感价值 | 领导满意度/社会影响力 | 情绪诉求型 |

**原则**：能算的一定要算，算不清的用类比，五维选最打动人的2-3个写透

**类型锚定**：
- 功能诉求型：优先呈现直接效益+成本节省，R段"数据说话"
- 情绪诉求型：优先呈现风险规避+战略价值，R段"安心保障"
- 资产诉求型：优先呈现直接效益+成本节省，R段"回报测算"
- 品牌诉求型：优先呈现战略价值+情感价值，R段"标杆效应"

**同一方案讲不同故事**：S/P/A三段可以一样，R段因人而异

## 使用流程

1. **确认弹药库**：检查学员提示词是否指定了弹药库
   - 已指定 → 读取并使用
   - 未指定 → 使用 question 工具询问
   - 学员无法提供 → 使用常规运营商弹药库
2. **读取客户背景资料**：理解客户场景、痛点、关键人
3. **判断材料充分性**：按"材料充分性判断"规则执行
   - 材料充分 → 告知学员判断结论，直接进入分析
   - 材料不够充分 → 联网搜索补充（仅采信官方权威来源），告知学员补充了哪些信息及来源
4. **读取弹药库**：匹配客户需求与产品能力
5. **执行五步法，产出第一层**：
   - Step 1：需求转译（4列表格+穿透结论）
   - Step 2：能力匹配（6维评估+弹药库匹配）
   - Step 3：产品组合（三层组合+组合逻辑）
   - Step 4：差异化定位（三维优势+竞品对比）
   - Step 5：价值量化（五维+类型锚定）
   - 输出：`[客户名称]客户五步法分析报告.md`（Markdown，存客户背景资料原目录）
6. **基于分析报告，产出第二层**：
   - 按SPAR模板结构生成正式方案建议书（Word/.docx，存客户背景资料原目录）
   - 文件命名：`[客户名称]客户SPAR方案建议书.docx`
   - 使用 docx skill 生成，确保中文排版规范
   - S/P/A 的叙事基于五步法分析结论，但用面向决策层的商业语言重新组织
   - R 段针对不同关键人类型锚定价值故事

## 关键提醒

- 面向决策层，语言要专业但易懂
- 突出差异化优势和价值量化
- 方案要有逻辑连贯性，不是产品堆砌
- 每个产品选型都要有明确的"解决什么需求"
- R段要针对不同关键人讲不同的价值故事
- 两层输出必须按序执行：先完成分析报告再写正式方案，分析报告是方案的素材来源
